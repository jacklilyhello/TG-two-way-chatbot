# 管理员使用

所有管理操作仅接受实例配置中的授权 TGID，且须来自该实例管理员 Forum 群组。匿名管理员、其他群组和未授权账号不能转发管理员消息或操作按钮。日志话题、管理命令、系统消息和资料卡不参与双向聊天。

## 登记与旧话题

- 在 General 发送 `/tj TGID`：登记用户，已有当前绑定则返回当前话题；首次登记不保证能够主动私信从未联系过 Bot 的用户。
- 在尚未占用的旧用户话题发送 `/tj TGID`：直接绑定该话题并保留历史。
- 用户已有 A 话题而当前 B 空闲：机器人要求确认/取消。确认前继续使用 A；确认时重新校验版本与占用情况。
- B 已属于其他 TGID：拒绝；不会附带解除另一用户。
- General 和系统日志话题始终不能绑定普通用户。

切换后旧话题停止普通转发，历史消息与新系统已经积累的映射保留。旧资料卡不能控制新的绑定。旧数据库不导入，因此已知旧用户应先在原话题手工 `/tj`，避免用户先联系时创建新话题。

## 聊天与资料卡

用户私聊进入当前话题，管理员在当前话题直接发送业务消息即可回复。支持文字、图片、视频、音频、语音、文件、贴纸和相册。引用只关联同一用户且方向正确的已知映射；接口不支持或找不到目标时降级，原因留在管理员侧。编辑仅更新 Bot 在对侧的副本，不改写用户或管理员本人原件；已删除内容不会通过编辑重新发送。

管理员原消息 👍 表示 Telegram API 确认投递，不表示已读。明确拉黑、明确失败和未知结果分别提示。反应失败单独记账，不能通过重发聊天内容修复反应。相册逐条记录结果，整组成功才标整体成功；部分失败或删除通过文字摘要如实说明。

置顶资料卡显示姓名、TGID、用户名、首次联系、可取得的头像和通用/苹果/安卓入口。无用户名时显示“未设置”，资料链接是否可打开受 Telegram 隐私和客户端支持影响。用户再次联系时更新可取得的资料，首次联系时间保持不变。

资料卡支持人工封禁/解禁、直达主页、清空此对话。封禁期间用户新消息与编辑不转发，用户端保持静默；仍持久记录已知用户私聊原件，供清空范围使用。

## 删除

回复指定业务消息发送 `/sc`，只删除映射对应的用户私聊端一条消息。相册也只删除回复的那一条。API 确认删除后管理员原消息改为 👎，普通单条成功不另发成功文字，不加删除线、不补发原消息副本。

资料卡“清空此对话”先确认，再保存当时已知范围。确认后新到的消息不纳入；确认前积压的旧内容不得在清空后重新投递。结果逐条区分已删除、未删除原因和未知。管理员历史、原消息与话题始终保留。旧系统没有记录的私聊无法追溯，数量未知。

“48 小时内”也不代表一定可删除。权限、Telegram 消息类型、时间规则和接口拒绝均以实际结果为准；不能把“消息不存在”当作本次确认删除成功。

## General 管理面板

| 命令 | 用途 |
| --- | --- |
| `/mb`、`/mb today` | 今日统计 |
| `/mb 7`、`/mb 30`、`/mb all` | 含今天的近 7/30 天、全部 |
| `/mb users [页码]` | 用户分页 |
| `/mb search TGID`、`/mb user TGID` | 用户详情、状态、统计、绑定与话题跳转 |
| `/mb settings` | 查看当前非密钥设置 |
| `/mb timezone Asia/Singapore` | 设置有效 IANA 时区 |
| `/mb start 文案` | 设置固定欢迎文案 |
| `/mb help 文案` | 设置固定帮助文案 |
| `/mb logtopic 话题ID` | 验证并指定未用作用户话题的专用日志话题 |
| `/mb unknown` | 查看外部操作未知结果，保留人工核查，不自动重发 |

文案为 1–3500 字符，支持 `{name}`、`{first_name}`、`{last_name}`、`{username}`、`{tgid}`；无用户名时 `{username}` 为“未设置”。用户主动 `/start`、`/help` 才触发这些固定文案，普通聊天不自动回复。

日志话题 ID 必须大于 1，且不能是当前或历史用户话题；Bot 会先发送一条验证消息，成功后再保存。未知结果列表用于核对操作状态，不能据此批量重发。

统计只包含新系统收到的双向业务原消息，相册按条数计算。命令、卡片、日志、编辑、重复更新和重试不增加原消息量。管理员成功率为成功除以“成功＋明确失败”，未知单列；活跃用户只计算范围内主动发送业务消息的不同 TGID。底层保存 UTC，默认按 Asia/Singapore 展示。密钥不在面板展示或编辑。
