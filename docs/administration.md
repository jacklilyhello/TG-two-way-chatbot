# 管理员使用

所有管理操作仅接受实例配置中的授权 TGID，且须来自该实例管理员 Forum 群组。匿名管理员、其他群组和未授权账号不能转发管理员消息或操作按钮。日志话题、管理命令、系统消息和资料卡不参与双向聊天。

转发的斜杠文本不执行管理命令。在管理员群内，Telegram 明确标记来源为 Bot、已配置管理员或本管理群的转发内容不会下发给用户，以避免转发日志、资料卡或管理结果。非管理员第三方来源及普通用户私聊中的正常转发保留。Telegram 隐藏来源或人工复制粘贴后无法可靠判断原始话题；此类普通文字仍按实际授权操作者与当前有效话题处理，不根据正文中的姓名、TGID 或日志关键词授予权限。

管理按钮绑定实例、操作者范围、原消息与话题；用户资料卡另校验当前用户、绑定版本与卡片。管理员业务消息和 `/sc` 保存入队时绑定版本，即使话题后来切走再切回，旧任务也不会借用新绑定继续发送或删除。升级前积压任务使用已保存的绑定历史时间进行兼容校验。

用户入站同样保存当时的绑定与封禁准入；恢复任务复用原始准入，解封或切回原话题不会使已阻断内容重新投递。新用户的首次绑定保留正常初始化路径。实际转发前再次检查封禁、绑定及删除状态；已发出的请求不能因随后状态变化而撤销。

## 登记与旧话题

- 在 General 发送 `/tj TGID`：登记用户，已有当前绑定则返回当前话题；首次登记不保证能够主动私信从未联系过 Bot 的用户。
- 在尚未占用的旧用户话题发送 `/tj TGID`：直接绑定该话题并保留历史。
- 用户已有 A 话题而当前 B 空闲：机器人要求确认/取消。确认前继续使用 A；确认时重新校验版本与占用情况。
- B 已属于其他 TGID：拒绝；不会附带解除另一用户。
- General 和系统日志话题始终不能绑定普通用户。

切换后旧话题停止普通转发，历史消息与新系统已经积累的映射保留。旧资料卡不能控制新的绑定。旧数据库不导入，因此已知旧用户应先在原话题手工 `/tj`，避免用户先联系时创建新话题。

## 聊天与资料卡

用户私聊进入当前话题，管理员在当前话题直接发送业务消息即可回复。支持文字、图片、视频、音频、语音、文件、贴纸和相册。引用只关联同一用户且方向正确的已知映射；接口不支持或找不到目标时降级，原因留在管理员侧。编辑仅更新 Bot 在对侧的副本，不改写用户或管理员本人原件；已删除内容不会通过编辑重新发送。

管理员原业务消息上的 👍 表示 Telegram API 确认投递，不表示已读。机器人成功设置 👍 后保留 10 秒，再通过持久任务取消自己的反应；实际设置、计划清理与确认清理时间分别记账。到期清理优先于新增成功标记，但仍遵守 Telegram 限流；限流、外部请求或恢复可能使实际取消晚于 10 秒，不能把计划时间当作实际完成时间。清理任务不阻塞该用户后续聊天，也不会清除真人反应。

明确发送失败使用 😢，并保留管理员侧原因说明；失败标记不执行 10 秒清理。处理、等待安全重试及结果未知不会显示成功，也不会冒充明确失败。成功发送而标记失败时只修复反应，不能重发聊天内容。旧清理任务校验当前状态和版本，不能清掉后来出现的 😢、删除成功 👎 或新回执。相册逐条记录结果，整组成功才标整体 👍；部分失败或删除通过文字摘要如实说明。

单条管理员业务消息被 Telegram 明确以 4xx 拒绝时，符合条件的失败通知显示“重试此条”。429 限流、409 状态取消、仍在处理、结果未知和相册均不提供此按钮。点击前应先排除原因，例如由测试用户解除对 Bot 的拉黑；按钮不会绕过 Telegram 的拒绝条件。

“重试此条”只接受原业务消息发送者本人，并且该账号仍须是实例授权管理员。按钮有效期为 15 分钟，绑定原失败通知、原业务消息、用户、群组、话题、当前绑定版本和恢复代次；过期、被删除或绑定变化的目标不能重试。重复点击同一失败通知只预约一次，任务在该用户队列中执行，并在实际发出前再次检查状态。它使用新的发送记录，保留此前失败，不新增业务原消息计数，也不额外通知普通用户。

重试等待期间保留原失败标记；Telegram 确认成功后，同一管理员原消息改为 👍 并按上述 10 秒规则清理。再次明确失败会产生对应的新失败通知；重试结果未知时不再提供按钮，也不会自动重发。失败通知及管理员原件始终保留。

置顶资料卡显示姓名、TGID、用户名、首次联系、可取得的头像和通用/苹果/安卓入口。无头像或用户名时仍保留三个入口；无用户名显示“未设置”。用户再次联系时更新可取得的资料，首次联系时间保持不变。

| 入口 | 有公开用户名 | 无公开用户名 |
| --- | --- | --- |
| 通用资料 | `https://t.me/<username>?profile` | Bot API 的 `tg://user?id=<TGID>` 资料按钮 |
| 苹果资料 | `tg://resolve?domain=<username>&profile` | Bot API 的 `tg://user?id=<TGID>` 资料按钮 |
| 安卓资料 | `tg://resolve?domain=<username>&profile` | `tg://openmessage?user_id=<TGID>` 兼容入口，可能打开对话而非资料页 |

Telegram [公开资料链接规范](https://core.telegram.org/api/links#public-username-links)支持用户名链接中的 `profile` 参数；[Bot API 资料按钮](https://core.telegram.org/bots/api#inlinekeyboardbutton)明确说明数字 ID 按钮受隐私设置限制。`tg://user` 在 Bot API 中转换为原生用户资料按钮，[不能视为所有客户端均能处理的独立网址](https://core.telegram.org/api/links#id-links)。安卓的 `openmessage` 由[官方客户端源码](https://github.com/DrKLO/Telegram/blob/master/TMessagesProj/src/main/java/org/telegram/ui/LaunchActivity.java)处理，是否成功仍依赖客户端是否认识该用户及版本、隐私等条件；不将此路径作为苹果或网页版通用入口，也不承诺数字 TGID 能绕过隐私。文档与源码核验不等于苹果、安卓真机验收。

新建话题按“创建话题 → 发送文字资料卡 → 确认置顶 → 投递用户第一条及后续业务消息”执行。首次初始化有持久门槛；并发到达的消息、相册和恢复任务复用同一张卡片及操作记录。初始化失败或结果未知时暂停该用户投递，保留记录供修复，不猜测成功或重复发送。新话题的资料卡保持文字形式并原位更新，避免后来头像更新把置顶卡片移到业务消息之后；资料入口仍保留。

已有话题的资料更新、`/tj`、封禁与解禁通过独立串行任务维护卡片，状态生效与展示更新可能存在短暂间隔。头像查询缓存 60 秒；姓名和用户名仍随新消息更新，管理员显式修复资料卡时绕过缓存。若 Telegram 明确以 `BUTTON_USER_PRIVACY_RESTRICTED` 拒绝 ID 链接按钮，机器人把三个资料入口及“直达对方主页”转换为获授权管理员可操作的兼容说明入口，保留 TGID 和管理按钮后完成整张卡片；未知结果不会因此重发。兼容说明提供复制 TGID，并解释从已有私聊或共同群进入资料的方式；安卓说明另包含可复制后尝试的兼容链接文本，不再依赖 ID 链接按钮发送说明。无法打开资料时仍可通过当前话题双向聊天。已缓存的 ID 限制不会隐藏入口，用户后来设置有效公开用户名后恢复公开资料链接。新旧资料卡均使用该逻辑。

资料卡支持人工封禁/解禁、直达主页、清空此对话。每次从正常变为封禁后，在对应管理员话题留下持久通知；重复点击、任务恢复及持续广告不会重复通知。自动封禁通知另列触发规则编号、类型及规则内容，只发送到管理员群。解除封禁会更新当前卡片状态和按钮；停用或删除规则不会自动解封。封禁期间用户新消息与编辑不转发，用户端保持静默；仍持久记录已知用户私聊原件，供清空范围使用。封禁时已排队的入站消息不会在解封后补投。

## 删除

回复指定业务消息发送 `/sc`，只删除映射对应的用户私聊端一条消息。相册也只删除回复的那一条。API 确认删除后管理员原消息改为 👎，普通单条成功不另发成功文字，不加删除线、不补发原消息副本。

资料卡“清空此对话”先确认，再保存当时已知范围。确认后新到的消息不纳入；确认前积压的旧内容不得在清空后重新投递。结果逐条区分已删除、未删除原因和未知。管理员历史、原消息与话题始终保留。旧系统没有记录的私聊无法追溯，数量未知。

清空每轮最多处理两条，在一条结果保存后检查约两秒的处理预算，再持久续跑，让已排队的按钮与新消息能在轮次间执行。不会中断已发出的删除请求；单次慢请求、平台限流和最后的相册汇总仍可能延后反馈，因此两秒不是整个清空操作的硬性完成期限。

相册部分删除仍报告逐条结果。若该入站相册从未设置 Bot 回执，不额外发送空反应；已有回执或可能设置成功但结果未知的回执仍按当前状态清理，不能保留过时的整组成功标记。

已经预约的重试也受删除范围约束。若重试已确认成功但消息映射尚未写完，删除会从最新重试的持久结果恢复已知私聊目标，包括引用降级后的结果；没有确认目标时如实报告，不能为了寻找目标重新发送内容。

“48 小时内”也不代表一定可删除。权限、Telegram 消息类型、时间规则和接口拒绝均以实际结果为准；不能把“消息不存在”当作本次确认删除成功。

## General 管理面板

| 命令 | 用途 |
| --- | --- |
| `/mb`、`/mb today` | 今日统计 |
| `/mb 7`、`/mb 30`、`/mb all` | 含今天的近 7/30 天、全部 |
| `/mb users [页码]` | 用户分页 |
| `/mb search TGID`、`/mb user TGID` | 用户详情、状态、统计、绑定与话题跳转 |
| `/mb settings` | 查看当前非密钥设置 |
| `/mb broadcast` | 打开管理员广播面板；也可点击主面板“管理员广播” |
| `/mb rules` | 打开交互式拦截规则管理 |
| `/mb rules add keyword 广告关键词` | 添加忽略大小写的原文子串规则 |
| `/mb rules add regex (优惠\|推广)\s*[0-9]+` | 添加区分大小写的安全正则规则 |
| `/mb rules on 编号`、`/mb rules off 编号` | 启用、停用指定规则 |
| `/mb rules delete 编号` | 删除指定规则（保留审计） |
| `/mb timezone Asia/Singapore` | 设置有效 IANA 时区 |
| `/mb start 文案` | 设置固定欢迎文案 |
| `/mb help 文案` | 设置固定帮助文案 |
| `/mb logtopic 话题ID` | 验证并指定未用作用户话题的专用日志话题 |
| `/mb unknown` | 查看外部操作未知结果，保留人工核查，不自动重发 |

文案为 1–3500 字符，支持 `{name}`、`{first_name}`、`{last_name}`、`{username}`、`{tgid}`；无用户名时 `{username}` 为“未设置”。用户主动 `/start`、`/help` 才触发这些固定文案，普通聊天不自动回复。

点击 `/mb` 的“拦截规则”，直接显示当前已启用且有效的规则编号、类型及内容，每页最多 5 条；没有有效规则时明确提示。停用或无效的历史规则继续保留，只是不列入有效列表。列表提供“添加规则”“删除规则”“规则说明”和“返回主面板”，现有命令仍兼容。

“添加规则”依次询问关键词或正则类型、规则内容，校验后显示待保存内容，点击“确认保存”才添加并启用。输入错误会说明原因，继续发送修正内容即可，不需要重新输入管理命令。“删除规则”先询问规则编号，再显示对应规则供确认；编号可以带 `#`，停用规则也可通过编号删除。确认时再次核对规则版本，其他管理员已修改的旧预览不会覆盖新状态。结果持久保存后立即显示轻提示，结果文案与更新后的有效列表合为一条消息；列表发送失败或未知会另行说明，不能把展示异常当作规则未保存。

每一步都有取消或返回入口；也可以直接发送“取消”“返回”或 `/cancel` 结束流程。输入 `/mb`、`/tj`、`/sc` 切换管理操作会结束旧流程。每一步有效期 15 分钟，过期、取消或完成后不会继续收取后续普通输入。规则内容可以以 `/` 开头，只有本机器人的上述管理命令会退出；带 `/.../flags` 的正则会说明格式错误并允许重新输入。

只允许授权管理员在 General 操作。流程草稿按实例、管理员及恢复周期隔离；按钮绑定原消息、操作者、流程步骤和规则版本，过时按钮不能覆盖后续修改。文字输入在 webhook 持久接收时记录所属流程，迟到输入不能进入后来新开的流程，也不会转发给用户。发送旧消息的编辑或转发不能冒充新步骤输入。每个 Bot 的规则及封禁状态保存在自己的 D1 中，正常升级与重启继续保留。

关键词按原文子串匹配，忽略大小写，内部空格及换行保留。正则同样搜索子串，区分大小写，`^`、`$` 可限定整条文字；直接输入表达式，不加 `/` 分隔符或 flags。支持字面量、`.`、字符类 `[]`、分组 `()`、选择 `|`、`*`、`+`、`?`、`{m,n}`、`\d`、`\w`、`\s` 及其大写反向类；不支持前后查找、回溯引用、内联标志。匹配文字和媒体说明（各取前 8192 个 UTF-16 字符），包含编辑；不读取附件内容、图片文字、姓名或用户名。相册收集完后检查各项说明，再发出整组。

最多保存 50 条未删除规则，其中正则最多 10 条；每条 1–200 字符，有限重复上限 40 次，单条最多 128 个匹配状态、合计最多 512 个。无效、过复杂或能匹配空串的正则拒绝保存。正则使用非回溯状态机，嵌套重复也不会造成指数回溯。规则按编号从小到大匹配，首条命中后封禁。第一条消息命中也会建立话题、置顶资料卡并记录封禁，不投递命中内容；用户端无通知。

每个消息任务在首次处理时保存匹配决定，相册在收集成员后统一保存。规则修改不追溯已开始投递的原任务；恢复会核对其已有发送结果，保留已确认映射及未知结果，不重新发送。用户后来编辑文字或说明属于新的匹配事件。

日志话题 ID 必须大于 1，且不能是当前或历史用户话题；Bot 会先发送一条验证消息，成功后再保存。未知结果列表用于核对操作状态，不能据此批量重发。

统计只包含新系统收到的双向业务原消息，相册按条数计算。命令、卡片、日志、编辑、重复更新、重试和广播不增加原消息量。广播结果在广播面板单独查看。管理员成功率为成功除以“成功＋明确失败”，未知单列；活跃用户只计算范围内主动发送业务消息的不同 TGID。底层保存 UTC，默认按 Asia/Singapore 展示。密钥不在面板展示或编辑。

## 管理员广播

在当前 Bot 的管理员 Forum 的 General 主话题发送 `/mb`，点击“管理员广播”→“新建广播”。后续均按按钮和提示操作，无须记忆子命令。

1. 发送一条文字（1–3500 字符），或单独上传一张图片；图片可以带说明。文字先输入时，可继续上传图片，图片说明会追加到已有文字；也可点击“仅文字，生成预览”。图片先输入时，可补充文字，或直接生成纯图片预览。每份广播只支持单张图片，相册和其他附件不会加入广播。
2. 查看完整内容预览，以及独立提示中的目标机器人、预计接收人数和范围。图片说明不超过 1024 字符时随图片发送；更长的文字按“图片、完整文字”两条消息展示和发送，不截断或省略。预览中的所有内容消息共同构成这一份广播；管理提示和按钮不属于广播正文。
3. 点击“第一次确认：内容和范围正确”。此时只保存第一次确认，不向用户发送。
4. 再次核对即将发送的机器人及人数，点击新提示上的“第二次确认：开始广播”，才启动正式发送。连续点击第一次确认不能代替第二次确认，重复点击开始按钮也不会重复创建发送。

正式发送前可以修改文字、修改图片、移除图片、返回预览或取消。任何修改或返回都会使之前的确认失效，必须重新生成完整预览并确认两次。直接发送“取消”“返回”或 `/cancel` 可结束草稿；切换 `/mb`、`/tj`、`/sc` 管理操作也会关闭旧流程。每一步 15 分钟有效；编辑旧输入不会修改草稿。草稿结束后不会继续收取后续输入。已经开始的广播按已确认范围处理，草稿取消不是撤回已发送消息。

仅当前实例获授权管理员可以在 General 创建和确认。会话按实例、管理员及恢复代次隔离；按钮还绑定原消息、流程和步骤版本，其他管理员、旧流程及旧按钮不能替代当前确认。普通用户私聊不会进入管理流程，也不会收到操作提示。

预览时冻结当前实例中未封禁且拥有当前有效话题的用户名单和预计人数；尚无有效话题的用户不加入。新加入用户不追加到已有广播。每份内容实际发出前再次检查用户状态、当前广播及收件范围；后来被封禁、失去有效话题或不再符合测试名单的对象跳过。名单和发送操作仅使用当前 Bot 自己的数据库、身份及资源。

测试实例 `test-a`、`test-b` 另外受私有 `BROADCAST_TEST_RECIPIENT_IDS` 限制，只有名单内且符合上述条件的用户可以接收；名单不授予管理员权限。缺失或无效时关闭测试广播发送。真实账号和名单值只存于私有 Secrets，不在面板中展示。本轮广播功能只发布到这两个测试实例，正式实例不随代码合并自动更新。

广播在独立发送通道中以保守节奏处理，遵守 Bot 共享额度及 Telegram 返回的 `retry_after`。单名用户明确失败或结果未知后继续处理其他用户。发送任务、每名收件人的内容进度及每部分的外部结果持久保存；队列重复、任务重试和同恢复代次的重新部署复用原记录，已经确认的部分不重发。连续执行异常可能需要管理员核查；数据库恢复改变代次时，旧广播中无法证明结果的未完成记录保留为未知，不盲目续发。

返回“管理员广播”可查看自己最近的广播，点击状态入口或“刷新状态”读取实际结果；正常结束时还会在 General 留下结果摘要。统计按收件人计算：

| 项目 | 含义 |
| --- | --- |
| 预计接收人数 | 完整预览时冻结的合格名单人数，后续不因跳过而改写 |
| 已确认成功 | 此人全部内容均取得 Telegram API 成功确认及有效消息标识；不代表已读 |
| 明确失败 | 内容被明确拒绝；多部分广播可能已有部分内容成功 |
| 未发送 | 仍在等待处理，或发送前因状态、范围变化被跳过 |
| 结果未知 | 请求可能已产生外部效果，但无法取得可靠结果；不自动重发 |
| 其中仅部分内容已确认 | 只有部分内容已确认成功，是失败、未知或未发送中的补充说明，不另外增加总人数 |

任务入队不算发送成功。广播保存已知私聊目标，供现有“清空此对话”快照按范围处理；管理员预览、原始输入、管理历史和话题保留。
